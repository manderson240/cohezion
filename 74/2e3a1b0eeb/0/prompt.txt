### Crash/Hang Files Identified

**1. Segfault — `tests/cache/test_sentence_encoder.py`**

- **Symptom**: Process aborts with `Fatal Python error: Segmentation fault` listing `torch._C`, `scipy`, `sklearn` in the extension module dump
- **Root cause**: The test calls `SentenceTransformerEncoder()` inside a `with patch("sentence_transformers.SentenceTransformer")` block. The `patch` target applies **after** `sentence_transformers` is imported for the first time inside `_load_model()`. Importing `sentence_transformers` eagerly loads `torch._C`. When `torch._C` is loaded into a process that has already loaded `scipy` + `sklearn` C extensions (from tests run earlier in the session), a memory allocator conflict in those native libraries causes the segfault. The exact trigger is torch's BLAS/LAPACK routines conflicting with scipy's OpenBLAS at shared library level.
- **Reproduce**: `uv run pytest tests/cache/test_sentence_encoder.py -q`
- **Fix**: Add a `conftest.py` guard in `tests/cache/` or skip this test when `sentence_transformers` is unavailable; or restructure the test to mock `sentence_transformers` at the module import level using `sys.modules` before the encoder is created.

**2. Infinite hang — `tests/universe/test_sandbox_manager.py`**

- **Symptom**: Process hangs indefinitely (SIGTERM at 60s), no output
- **Root cause**: Tests in `TestSandboxManagerExecution` use `@pytest.mark.anyio`. The `run_simulation` method calls `_register_with_monitor` and `_deregister_with_monitor` (lines 174, 200 of `/home/mike-anderson/dev/cohezion/src/cohezion/universe/sandbox_manager.py`) which call `get_resource_monitor()`. `ResourceMonitor.__init__` (line 64 of `/home/mike-anderson/dev/cohezion/src/cohezion/reliability/monitor.py`) runs `loop.create_task(self._heartbeat_loop())` when an event loop is running. The anyio runner provides a live event loop during the test. The `_heartbeat_loop` is a `while self._running: ... await asyncio.sleep(2)` infinite loop. When anyio's test runner finishes and tries to shut down the event loop, the heartbeat task is still running, causing `loop.run_until_complete()` to block forever.
- **Note**: The `_wait_for_backpressure` is correctly mocked, but `_register_with_monitor` and `_deregister_with_monitor` are not mocked and still trigger `ResourceMonitor` instantiation.
- **Reproduce**: `uv run pytest tests/universe/test_sandbox_manager.py::TestSandboxManagerExecution::test_run_simulation_success -q`
- **Fix** (three options):
  - **Option A (preferred)**: Mock `_register_with_monitor` and `_deregister_with_monitor` in the `TestSandboxManagerExecution` tests, matching the pattern used for `_wait_for_backpressure`
  - **Option B**: Add teardown to call `monitor.stop()` after each anyio test, or add a `reset_manager`-style fixture that also cancels the heartbeat task
  - **Option C**: In `ResourceMonitor.__init__`, only start the heartbeat task when explicitly started (not automatically on init), and add a separate `start()` method

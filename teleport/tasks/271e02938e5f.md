# Vault Knowledge Graph Densification: Cross-Link Papers ↔ Concepts ↔ Decisions

## Context

The vault currently has ~95 papers in papers/, 40+ concepts in concepts/, and dozens of decisions/patterns. Cross-linking is sparse — papers often don't wiki-link to relevant concepts, concepts lack backlinks, and the SurrealDB graph has thin `links` edges.

Key files:
- `projects/vault-knowledge-graph-densification.md` — full project spec with success criteria
- `CLAUDE.md` — vault structure conventions
- `HANDOFF.md` — current repo state (branch: track-c)

MCP tools available locally: vault_read, vault_edit, vault_backlinks, vault_forward_links, vault_search, vault_tags, surrealdb_import_papers, surrealdb_import_concepts, surrealdb_query

Critical conventions:
- Tags must be arrays in frontmatter: `tags: [ai, architecture]`
- Wiki-links use `[[note-name]]` format
- Don't rewrite entire notes — use surgical `vault_edit` operations
- Branch is `track-c`, commit after each batch

## Description

Systematically audit and cross-link all ~95 papers and ~40+ concepts in the vault to densify the SurrealDB knowledge graph. This is the single highest-leverage vault maintenance task: every future `vault_find_relevant_context` call, every agent session, and every research query gets dramatically better when the graph has dense, accurate links.

See `projects/vault-knowledge-graph-densification.md` for full spec.

**Phase 1** (~2-3h): For each paper in `papers/`, read it, identify which concepts it should link to, add missing `[[concept]]` wiki-links, ensure `similar_papers` frontmatter, and add `## Cohezion Integration` sections where missing.

**Phase 2** (~1-2h): For each concept in `concepts/`, check backlinks, flesh out stubs, add `related_concepts` frontmatter.

**Phase 3** (~30m): Re-import to SurrealDB via `surrealdb_import_papers` and `surrealdb_import_concepts`, verify link density.

**Phase 4** (~30m): Run validation queries to find orphans and gaps.

Approach: Work through papers alphabetically, batch of 10 at a time. Use `vault_read` + `vault_edit` (surgical edits, not full rewrites). Use `vault_backlinks` and `vault_forward_links` to audit connectivity. Commit after each batch of 10 papers.

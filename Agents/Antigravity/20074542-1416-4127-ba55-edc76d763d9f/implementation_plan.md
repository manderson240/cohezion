# [Cohezion] VLIW Optimization Plan (FLUME-01)

## Goal Description
Optimize a VLIW (Very Long Instruction Word) kernel to minimize cycle count for a tree traversal/hashing algorithm, aiming to beat the 1487 cycle threshold. We will employ **FLUME** (Fluid Latent Understanding through Manifold Encoding) to navigate the optimization landscape.

## User Review Required
> [!IMPORTANT]
> This plan assumes the "Smart Load" logic in `optimizer.py` is the current best candidate for optimization but requires debugging (NotImplementedError mentioned in history).

## Proposed Changes

### Component: `optimizer.py`

#### [MODIFY] [VLIWPacker]
- **Dependency Tracking**: Improve `add_slot` to pack instructions more tightly involving memory operations (`is_mem_read`, `is_mem_write`).
- **Lookahead**: Potentially implement a lookahead buffer to reorder independent instructions.

#### [MODIFY] [OptimizedKernelBuilder]
- **Smart Load Logic**: Increase threshold to `<= 16` nodes (Rounds 0-4). Theoretical analysis shows Global Load Bandwidth savings outweigh Local ALU Latency cost.
- **Register Allocation**: Reverted to `N_VEC=16` (Best Baseline) with Hoisted Constants and Unique Addresses. "Hail Mary" `N_VEC=32` proved inefficient due to loop overhead.
- **FLUME Probe**: Research confirmed `idx` is random; no prediction logic added.
- **Vectorization**: Pure vector strategy.

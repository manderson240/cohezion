#### 2.6 Persistent Kernel Scheduling on CDNA4/MI355X

**Sources**:
- [HipKittens Framework (MI355X specifics)](https://arxiv.org/html/2511.08083v1)

- [FP8 GEMM Optimization on CDNA4](https://rocm.blogs.amd.com/software-tools-optimization/cdna4-gemm-kernels/README.html)

**MI355X Architecture**:
- 256 compute units organized into 8 accelerator complex dies (XCDs) of 32 CUs each
- Chiplet layout with hierarchical cache structures (L2 per XCD, LLC across chiplets)
- Hardware scheduler assigns thread blocks to XCDs in round-robin order

**Persistent Kernel Scheduling Challenge**:
- Naive row-major thread block allocation: 36% L2 hit rate for BF16 GEMM
- Cache hierarchy mismatch: Optimizing for L2 alone degrades LLC performance
- HipKittens solution: Block swizzling in "chunks" assigned to XCDs, tile traversal in vertical windows
  - Result: Up to 19% bandwidth improvement over naive allocation

**Key Principle**: Chiplet-aware scheduling is mandatory for CDNA4 efficiency — ignoring XCD topology leaves significant performance on the table.

**Connection to Internal Work**: The "reference.py" baseline kernels use CK's XCD-aware scheduling; shape-dependent routing (v5+) likely exploits different optimal schedules for different problem sizes.

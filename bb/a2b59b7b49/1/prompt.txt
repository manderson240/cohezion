## Security Review: version-watch.sh, on-permission-denied.sh, settings.json, cost_aware_router.py, api_llm_executor.py, surrealdb.service

### Summary

The codebase has a well-structured local development setup with no committed secrets and generally sound defensive practices. The highest-priority finding is a genuine shell injection vector in `on-permission-denied.sh` where attacker-controlled tool names are passed unsanitized as regex patterns to `grep -E`. Three additional medium-severity gaps round out the findings: `--allow-scripting` in SurrealDB, a missing API key null-guard before use, and an insufficiently broad safe-retry pattern that could be abused conceptually.

---

### Findings

#### HIGH

- `/home/mike-anderson/.claude/hooks/on-permission-denied.sh:23` — **Unsanitized tool name passed as a `grep -E` regex pattern.** The `TOOL_NAME` value is extracted from JSON stdin (which an LLM or MCP tool invocation populates) and then fed directly into `grep -qE "$pattern"` at line 23 via the `echo "$TOOL_NAME" | grep -qE "$pattern"` loop. An attacker who can influence a tool name — e.g., via a malicious MCP server supplying a tool named `Bash(cat:` followed by a crafted string — can cause `grep` to interpret arbitrary POSIX ERE regex. While `grep -E` regex injection does not yield OS command execution, a carefully crafted name like `Bash(cat:.*` would match every pattern in the safe list and force an unconditional `{"retry": true}` response, silently bypassing the permission denial for any tool the attacker chooses to name that way. Concretely: a malicious MCP server registers a tool named `^Bash\(ls:` and its denial is auto-retried because the whole pattern file matches the tool name when the loop pattern happens to be the one containing that text. The real risk is **forced auto-retry of a legitimately-denied dangerous tool** by crafting a tool name that matches one of the safe patterns. Remediation: treat `TOOL_NAME` as data, not a regex subject; compare with fixed-string (`grep -qF`) against literal safe prefixes, or normalize the tool name to strip non-alphanumeric characters before pattern matching.

#### MEDIUM

- `/home/mike-anderson/.config/systemd/user/surrealdb.service:18` — **`--allow-scripting` enables server-side JavaScript execution inside SurrealDB queries.** Any code path that constructs SurrealQL from user-supplied data (even partially) could execute JavaScript on the DB server with access to the SurrealDB process's file-system permissions and network. Binding to 127.0.0.1 reduces but does not eliminate this risk — any local process, compromised dependency, or SSRF vector in the FastAPI service could reach port 8001 and issue a scripted query. Remediation: remove `--allow-scripting` unless there is an active and documented requirement for JS-in-queries; audit all SurrealQL construction paths for injection. The `root/root` credentials are flagged here only because they are combined with `--allow-scripting`; standalone they are acceptable per the CLAUDE.md note on local-dev credentials.

- `/home/mike-anderson/dev/cohezion/src/cohezion/integrations/agentverse/api_llm_executor.py:97-98` — **Missing API key is logged as a warning but execution continues; the key is then dereferenced unconditionally inside the `Authorization` / `x-api-key` header at lines 155 and 211.** If `self.api_key` is `None`, the header value is the string `"Bearer None"` or `None` directly, which leaks the fact that no key is configured and may cause an obscure 401 to propagate rather than a clear startup failure. More importantly the warning at line 98 goes to the logger at `WARNING` level — if a log aggregator is watching, the message `No API key found for anthropic` appears in logs tied to session context that could reveal which providers are configured. - `/home/mike-anderson/dev/cohezion/src/cohezion/swarm/cost_aware_router.py:316` — **`Path(__file__).parents[2] / "config" / "model_profiles.yaml"` resolves relative to the installed package location, not the project root.** In a production or editable-install scenario where `__file__` is inside a `.venv` or a built wheel, this path traversal silently falls back to `Path("config/model_profiles.yaml")` (CWD-relative). #### LOW

- `/home/mike-anderson/.claude/settings.json:84` — **`Bash(env:*)` permission allows the agent to run `env` with arbitrary arguments.** On Linux, `env COMMAND ARGS` executes `COMMAND`. ## 1. Agent Verification &amp; Formal Methods

### The "Vericoding" Paradigm -- GENUINELY DEFENSIBLE

The most important development is **vericoding**: LLMs generate code AND formal proofs of correctness, which are then checked by a verified proof kernel. The key insight, articulated by [Martin Kleppmann (Dec 2025)](https://martin.kleppmann.com/2025/12/08/ai-formal-verification.html): it does not matter if the LLM hallucinates nonsense, because the proof checker rejects invalid proofs. The checker is a small, verified piece of code -- virtually impossible to fool.

**Key systems:**

- **AutoRocq** ([arXiv 2511.17330](https://arxiv.org/abs/2511.17330)) -- First agentic proof automation system. Uses iterative LLM-prover dialogue: the agent generates tactics, gets feedback from the Rocq (Coq) theorem prover, and refines. Outperforms baselines by 42-205% on real C programs from SV-COMP. Average proof time: 21.3 seconds. Verified 12 lemmas for Linux kernel module correctness. **Verdict: genuinely defensible** -- every output is machine-checked.

- **ProofWright** ([arXiv 2511.12294](https://arxiv.org/pdf/2511.12294)) -- Formal verification of LLM-generated CUDA kernels. Provides end-to-end guarantees of memory safety, thread safety, and semantic correctness. Verifies safety for 74% of generated kernels with ~3 minute overhead per kernel. **Directly relevant to Cohezion's GPU kernel work.**

- **Apple's Hilbert** ([NeurIPS 2025 MATH-AI Workshop](https://machinelearning.apple.com/research/hilbert)) -- Multi-component orchestration: informal LLM reasoner + specialized Lean 4 prover + formal verifier + semantic theorem retriever. Achieved 99.2% on miniF2F (6.6% above best public method), 70.0% on PutnamBench (vs 50.4% for SeedProver).

- **Mistral Leanstral** (March 2026) -- Open-source AI agent purpose-built for Lean 4 formal proofs. Benchmark score 26.3 on FLTEval at pass@2, beating Claude Sonnet (23.7) at $36 vs $549 cost.

- **VeriCoding Benchmark** ([POPL 2026](https://popl26.sigplan.org/details/dafny-2026-papers/13/A-benchmark-for-vericoding-formally-verified-program-synthesis)) -- 12K+ tasks across Lean, Dafny, and Verus. Reveals large performance gaps. **CLEVER** (Thakur et al., 2025) shows the reality check: models solve only 1 of 161 Lean tasks requiring both spec and proof.

- **Astrogator** ([arXiv 2507.13290](https://arxiv.org/abs/2507.13290)) -- Produces formal specifications of user intent to verify LLM-generated Ansible code. Verifies correct code in 83% of cases, identifies incorrect code in 92%.

### The "Memory vs. Learning" Distinction

This is critical: **memory** = stored text the agent can retrieve. **Learning** = behavioral change from accumulated experience. Current systems mostly do memory. Genuine learning requires either fine-tuning (catastrophic forgetting risk), in-context learning (context window limits), or hybrid architectures (MemRL, Jan 2026: runtime RL on episodic memory). **Cohezion's SkillRefiner + RetrospectionEngine is architecturally closest to genuine learning** -- it extracts patterns and updates skill definitions, changing future behavior.

## 6. Multi-Agent Coordination That Works Reliably

### Hallucination Cascades -- CRITICAL RISK

[Cogent Info Playbook 2026](https://cogentinfo.com/resources/when-ai-agents-collide-multi-agent-orchestration-failure-playbook-for-2026) documents the pattern: Manager agent accepts hallucinated data from Researcher. Downstream agents (Coders, Strategists, Analysts) treat it as truth. System reports high confidence because multiple agents reinforce the same false premise. **Confidence masking makes this particularly dangerous.**

[ICLR 2026 findings](https://llmsresearch.substack.com/p/what-iclr-2026-taught-us-about-multi-e9c) confirm: when agents relay information through text, errors compound. Small initial hallucination snowballs into total system failure.

### KVComm -- Bypassing Text-Based Cascades (GENUINELY DEFENSIBLE)

**KVComm** ([ICLR 2026](https://openreview.net/forum?id=F7rUng23nw), [GitHub](https://github.com/Zephyroam/KVComm)) proposes sharing Key-Value pairs instead of generated text between agents. Uses layer-wise selection based on attention importance scores with Gaussian prior. 30% of layers' KV pairs achieves near-full performance. **This directly prevents hallucination cascades because the receiver gets internal representations rather than potentially hallucinated text outputs.**

### MetaGPT Pattern -- Structured Workflow Verification

MetaGPT reduces cascading hallucinations by verifying intermediate results at each workflow stage. **Cohezion's compound loop with RequestAlignmentAnalyzer at each step already implements this pattern.**

### Politeness Spiraling Detection

A novel 2026 finding: when agents get stuck, they become increasingly polite and repetitive. Circuit Breakers detect this linguistic signature as logic circularity. **Easily implementable as a DegradationDetector heuristic in Cohezion.**

### Formal Coordination Protocols

- MCP (Anthropic) for agent-to-tool connections
- A2A (Google/Linux Foundation, 150+ orgs) for agent-to-agent with Agent Cards
- ACP for lightweight messaging
- NLIP (Ecma International, Dec 2025) for communication without shared ontologies
- **Open Reward Standard (ORS)** extends MCP with RL primitives: episodes, reward signals, task splits, curriculum management

## Project Overview: AMD × GPU MODE Speedrun (Phase 1)
**Goal:** Become a finalist in the E2E Model Speedrun (March 2026).
**Focus:** High-performance kernel optimization for DeepSeek-R1 (MLA/MoE) and Kimi-V3.
**Role:** Lead Developer (Background: Data Quality Engineering & Autonomous Agent Systems - Cohezion).

## Technical Environment
* **Target Hardware:** AMD Instinct MI355X (CDNA 4 architecture) via ROCm 6.3+.
* **Local Development:** Framework Desktop (128GB RAM) for logic validation and CPU-side orchestration.
* **Remote Environment:** Shared ROCm runners with **zero administrative control**.
* **Primary Constraints:** 1. No access to hardware counters (`rocprof`, `ncu`, `omnitrace`).
    2. High jitter/noisy-neighbor environment on evaluation nodes.
    3. Ephemeral filesystems (need persistent `TRITON_CACHE_DIR` strategies).

## Development Stack
* **Language Choice:** Deciding between raw **Triton (`@triton.jit`)** for maximum control and **Helion (Tiled PyTorch)** for rapid fusion prototyping and automated autotuning.
* **Kernel Targets:** - Multi-head Latent Attention (MLA) fusion (Up-projection + Attention).
    - MoE (Mixture of Experts) router and GEMM optimization.
    - FP8 / MXFP4 precision implementations.

## Optimization Strategy (Phase 1)
* **Synthetic Profiling:** Relying on robust `torch.cuda.Event` timing loops and arithmetic intensity calculations (Throughput vs. HBM bandwidth) rather than direct hardware telemetry.
* **Fusion-First:** Minimizing HBM round-trips by fusing activation/normalization directly into the main compute kernels.
* **Precision:** Prioritizing numerical parity ($1e^{-3}$ tolerance) while pushing the limits of the CDNA 4 instruction set.

## Prompting Instructions
When suggesting code or architectural changes:
1. Prioritize **Triton kernel fusion** logic.
2. Assume a senior engineering level—skip the basics of CUDA/ROCm.
3. Focus on "AMD-friendly" tiling (CDNA 4 specifics like matrix core utilization).
4. Suggest **autotuning search spaces** suitable for Helion.

# Long-Horizon Token-Efficient Dogfooding Plan

## Executive Summary
As the Cohezion platform ascends to full agentic autonomy via the Systems Engineering V-Model, Autonomy Engine, and A2A Protocol, the primary risk shifts from capability failure to resource exhaustion. A "Long Horizon" mission (e.g., overnight autonomous Kaggle competitions or days-long architecture refactors) can quickly drain the context window and the API budget if not strictly managed.

This plan details a token-efficient "dogfooding" protocol: using the platform to improve the platform overnight, specifically utilizing the Autoresearch Daemon and AgentSkills integrations, while remaining under the $50/day API budget and adhering to the 3-model local concurrency limit.

## 1. The Token Economy

### 1.1 Model Tier Rotation (Quarter-on-a-String Protocol)
To ensure long-horizon endurance, the platform will utilize a 4-tier compute fabric:
- **HOT Tier (Local, Free, Constant)**: `phi4-mini` (math/logic) and `nomic-embed-text` (RAG/linking). Used for 70% of operations, specifically continuous `mcp-guard`, `async-guard`, and `Latent Linker` operations.
- **WARM Tier (Local, Free, On-Demand)**: `qwen3-coder:30b` (implementation) and `deepseek-r1:14b` (emergence/biology). Spawned only when a deterministic AutoHarness fails or a hypothesis requires structured validation.
- **COLD Tier (Local, High-VRAM)**: `nemotron-3-super:120b` or `gemma3:4b`. Used strictly for overnight batch processing of deep geometric correspondence mappings (Awesome-Latent-Space).
- **CLOUD Tier (API, Paid)**: `gemini-2.5-pro` (Architecture) and `claude-3.5-sonnet` (Complex Implementation). *Strictly gated*. Only the `System Architect` operating at `Z2_4` or `HIHO` autonomy may escalate to this tier for final V-Model validation.

### 1.2 Context Compression (The Ouroboros Shedding)
Agentic memory must not grow linearly. 
- At the end of every active session, the `kg_guard` and `omega_distiller` will precipitate learnings.
- Once precipitated, the raw `journey_*.json` trajectories are flushed from the active context window and compressed into 256D `FlumeVAE` thought vectors in SurrealDB.
- Future agents will only load the 3 most relevant learnings via `pre-flight-rag.sh`, keeping the context window fixed in size regardless of the mission's duration.

## 2. Overnight Dogfooding Mission: "Project Geometric Alignment"

### Objective
Deploy the swarm overnight to autonomously research, validate, and implement new latent space topologies into the `FlumeVAE` architecture, consuming zero paid API tokens.

### Execution Loop (8:00 PM to 6:00 AM)

**Step 1: Autoresearch (8:00 PM)**
- The `autoresearch_daemon.py` polls arXiv and HuggingFace for recent papers on "Latent Space Geometry" and "Persistent Homology."
- It extracts hypotheses and stages them in `data/universe/`.

**Step 2: Latent Linking (10:00 PM)**
- The `LatentLinker` (using `nomic-embed-text` on the HOT tier) encodes the hypotheses into 256D vectors.
- It queries SurrealDB for overlaps with existing Cohezion trajectory data.

**Step 3: Systems Engineering Swarm (12:00 AM)**
- For any hypothesis with a >0.85 overlap, the A2A protocol awakens the `Physics Engineer` and `Quantum Algorithm Specialist`.
- Working in the WARM tier (`qwen3-coder:30b`), they synthesize a deterministic AutoHarness in `tests/harnesses/` to prove the geometric correspondence math.

**Step 4: AgentSkills Validation (3:00 AM)**
- The `AgentSkillsBridge` executes the harness against the existing `FlumeVAE` code.
- If the harness fails, the `Coherence Governor` logs a violation. If it passes, the hypothesis is marked as a valid `[POLICY]`.

**Step 5: OMEGA Distillation (6:00 AM)**
- The `omega_distiller.py` awakens, parses the validated hypotheses, and auto-generates permanent deterministic Python policies in `src/cohezion/policies/`.
- The system commits the new policies and resets for the day.

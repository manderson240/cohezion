## Definition

This runbook covers the operational procedures for managing the Ollama MCP server that provides embedding generation and vector search capabilities to the Cohezion vault. Ollama runs locally on port 11434 and serves as the embedding backend for [[semantic-search]] across vault content. The MCP integration wraps Ollama's API with tools for embedding, querying, batch operations, and model management.

Ollama is an open-source local LLM runtime that serves models via a REST API, providing the same interface pattern as cloud APIs but running entirely on local hardware. For Cohezion, Ollama's primary role is embedding generation -- converting vault notes into vector representations that enable similarity-based retrieval, complementing the keyword-based search and [[wiki-links|wiki-link]] graph traversal.

## Key Properties

- **Cold-start latency**: Ollama models take 5-30 seconds to load on first request; pre-warming is essential for pipeline performance.
- **Model selection**: Use `select_model` to choose the appropriate model for the task (embedding vs. generation).
- **Resource management**: Ollama consumes significant RAM when models are loaded; monitor memory usage.
- **Health checking**: `curl http://localhost:11434/api/version` confirms the service is running.
- **Timeout configuration**: The MCP wrapper is configured with a 30-second timeout to accommodate cold starts.

## Operational Procedures

### Start/Restart Ollama
```bash
# Check if running
curl -s http://localhost:11434/api/version

# Start service
ollama serve &

# Verify health
curl -s http://localhost:11434/api/tags | python3 -c "import sys,json; print(json.dumps(json.load(sys.stdin),indent=2))"
```

### Pre-warm a Model
```bash
# Load model into memory without generating output
curl -s http://localhost:11434/api/generate -d '{"model":"nomic-embed-text","prompt":"warmup","stream":false}' > /dev/null
```

### Check Loaded Models
```bash
curl -s http://localhost:11434/api/ps
```

### Common Failure Modes
1. **Service not running**: Ollama process crashed or was not started. Restart with `ollama serve`.
2. **Model not found**: Requested model not pulled. Run `ollama pull <model-name>`.
3. **OOM kill**: Model too large for available RAM. Switch to a smaller model or free memory.
4. **Port conflict**: Another process on 11434. Check with `lsof -i :11434`.

## Architecture Context

The Ollama MCP server sits in the Cohezion infrastructure stack as follows:

```
Agent → MCP Client → Ollama MCP Wrapper (stdio) → Ollama REST API (port 11434) → Local GPU/CPU
```

The MCP wrapper exposes five tools: `embed` (generate embeddings), `query` (vector search), `batch` (bulk operations), `select_model` (model management), and `status` (health check). These tools are configured in `~/.claude/mcp.json` and available to Claude Code sessions via the [[mcp-model-context-protocol|MCP protocol]].

## Relevance to Cohezion

Ollama powers the [[semantic-search]] layer of the Cohezion vault. When agents need to find conceptually related notes (not just keyword matches), they rely on embeddings generated by Ollama. The embedding model (typically `nomic-embed-text`) uses [[self-attention-mechanism|self-attention]] to produce context-aware vector representations of each note, enabling similarity-based retrieval that captures meaning rather than just vocabulary overlap.

Keeping Ollama operational and pre-warmed is critical for agent performance -- a cold Ollama means 5-30 seconds of latency on the first [[semantic-search|semantic query]] of every session. The [[runbook-health-checks|health check runbook]] includes Ollama-specific probes to catch service failures before they impact agent workflows.

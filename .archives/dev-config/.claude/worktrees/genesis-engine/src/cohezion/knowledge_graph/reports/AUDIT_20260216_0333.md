## 3. CRITICAL GAPS IDENTIFIED

### Gap 1: Retrospection Engine Is Stateless (SEVERITY: HIGH)
**Location:** `src/cohezion/core/compound/retrospection.py:89-137`

- Reads only `KEY_LEARNINGS.md` (static file)
- No vault queries for historical execution patterns
- No persistence of retrospection decisions
- No temporal learning across sessions
- **Impact:** Each session starts from zero context. The "compound" in compound engineering doesn't compound.

### Gap 2: Skill Refinement Has No Provenance (SEVERITY: HIGH)
**Location:** `src/cohezion/compound/skill_refiner.py:254-307`

- Refinements written to PRIME files with timestamp + metrics
- NO `execution_id` or task link
- No refinement history log (in-place file rewrites)
- Cannot answer: "Which execution caused skill v1.0.3?"
- **Impact:** Refinements are untraceable. Cannot audit skill evolution. Cannot learn which execution contexts produce valuable refinements vs noise.

### Gap 3: CompoundFeedbackLoop Is Orphaned (SEVERITY: HIGH)
**Location:** `src/cohezion/compound/feedback_loop.py`

- 587 lines of sophisticated retry logic (strategy selection, anomaly-based re-execution, batch feedback)
- NOT integrated into CompoundExecutor's 10-step pipeline
- Must be explicitly called by external code
- Learning from retries not persisted to vault
- **Impact:** The system cannot self-correct during execution. Anomalies are detected (Step 5) but never trigger automatic re-execution.

### Gap 4: No Closed-Loop Refinement Tracking (SEVERITY: MEDIUM)
- Skills are refined -> versions bumped -> files updated
- But no record flows back to vault saying "skill X was refined because of execution Y"
- SkillSelector cannot distinguish "this skill was recently refined and improved" from "this skill hasn't changed in weeks"
- **Impact:** Skill selection is blind to skill evolution trajectory.

### Gap 5: Compound Cycle Driver Is Mock-Only (SEVERITY: LOW)
**Location:** `scripts/drivers/compound_cycle.py`

- Uses mock MCP client, mock inflection detector, mock universe engine
- `--production` flag exists but requires live services
- No continuous cycling mode
- **Impact:** Cannot validate real vault/persistence workflows end-to-end.

## 4. THE TASK: Wire the Compound Feedback Loop into the Executor with Refinement Provenance

### Why This Is THE Task for Claude Code

The compound engineering loop is 95% complete. All 10 steps work. Skills are refined. Journeys are tracked. But three critical wires are disconnected:

1. **The FeedbackLoop exists but isn't plugged in** (587 lines of working retry logic, unused)
2. **Retrospection decisions are ephemeral** (no vault persistence, no temporal learning)
3. **Refinements have no provenance** (can't trace back to originating execution)

Connecting these three wires transforms Cohezion from "a pipeline that executes" into "a pipeline that learns from its own failures and remembers why it changed."

### Why Claude Code Specifically

This task is perfectly suited for autonomous claude.ai/code execution because:

1. **Bounded scope**: 3 integration points across 4 existing files. No greenfield architecture.
2. **All components exist**: FeedbackLoop, RetrospectionEngine, SkillRefiner, Executor are all written and tested. This is wiring, not invention.
3. **Clear test surface**: 775 existing compound tests define the contract. Integration tests in `test_compound_cycle.py` and `test_executor_skill_refiner_integration.py` provide the validation template.
4. **Self-verifiable**: Run `uv run pytest tests/compound/ -v` at each step. No human judgment needed.
5. **Non-destructive**: All changes are additive (new fields, new integration points). Existing behavior preserved via optional parameters.
6. **Follows CLAUDE.md exactly**: "Implement ONE feature, validate manually, write 5 tests" — three small features, each testable independently.

### Implementation Spec

#### Phase 1: Refinement Provenance (SkillRefiner)
Add `execution_id` and `task_description` to refinement records in `skill_refiner.py:254-307`. Create a `refinement_log.jsonl` alongside PRIME files for indexed lookup. ~50 lines changed.

#### Phase 2: Retrospection Persistence (RetrospectionEngine)
Add vault logging to `analyze_execution_result()` in `retrospection.py:365-460`. Persist `should_refine` decisions with context so future retrospections can query "what happened last time this skill had coherence < 0.5?" ~80 lines changed.

#### Phase 3: FeedbackLoop Integration (CompoundExecutor)
Wire `CompoundFeedbackLoop` into Step 5→7 of the executor. When InflectionDetector finds CRITICAL anomaly AND retries are enabled, delegate to FeedbackLoop before proceeding to retrospection. ~100 lines changed in `executor.py`.

#### Phase 4: Validation
- 5 tests for provenance (refinement → execution traceability)
- 5 tests for retrospection persistence (vault logging, historical queries)
- 5 tests for feedback loop integration (anomaly → retry → success path)
- Run full compound suite: `uv run pytest tests/compound/ -v`

### Expected Outcome
After this task, the compound loop becomes **truly compound**:
- Skill refinements are traceable to their source executions
- Retrospection decisions persist and inform future gating
- Critical anomalies trigger automatic re-execution with learned improvements
- The system remembers WHY it changed, not just THAT it changed

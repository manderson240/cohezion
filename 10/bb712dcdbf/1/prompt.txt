# Phase 4 Implementation Plan: Decision Analysis UI + Reasoning Chain Visualization

## Context

**What We Have** (Phases 1-3):
- **Phase 1**: SurrealDB 5-node schema (session, decision, action, outcome, lesson) + 8 edges
- **Phase 2 Track A**: Extended schema with `agent_reasoning` nodes + 4 new edge types (informs_reasoning, challenges_lesson, relates_to_decision, validates_reasoning) + 12 indexes
- **Phase 2 Track A Tools**: 3 MCP tools (record_reasoning, record_challenge, record_cascade) + 5 query patterns (root_cause, contradiction_detection, cascade_impact, high_confidence_reasoning, reasoning_by_type)
- **Phase 3**: Interactive 3D graph visualization of 84 papers with 8 semantic dimensions (connectivity, depth, temporal, domain, completion, recency, similarity)

**What's Missing** (Phase 4):
Users can see 84 papers in 3D and understand their relationships, but **cannot see WHY decisions were made or how decisions cascade through the system**. There's no visual representation of:
- Decision reasoning chains (root_cause_analysis query results)
- Downstream decision impacts (cascade_impact analysis)
- Contradictions between decisions and operational evidence (contradiction_detection)
- High-confidence reasoning clusters (reasoning patterns)

Additionally: **No dynamic paper ingestion** — when new papers are added to the vault as research progresses, the 3D graph doesn't automatically update. Users must manually reload the plugin.

**Problem**: The 3D graph shows PAPERS, but Phase 2 SurrealDB contains 88 DECISIONS with rich reasoning chains. These two systems are separate. Paper updates are not dynamic.

**Solution**: Extend Phase 3 plugin with a **Decision Analysis UI** that:
1. Overlays decision nodes on the 3D graph (or shows adjacent panel)
2. Visualizes reasoning chains as interactive flowcharts
3. Shows decision cascades as network graphs
4. Highlights contradictions (decisions vs lessons/evidence)
5. Queries SurrealDB via MCP tools for real-time reasoning data
6. **Dynamically ingest new papers** as they are added to the vault (file watcher + GraphData refresh)

**Outcome**: Users can explore "Why was this paper chosen?" → "What decisions reference it?" → "What reasoning supports those decisions?" → "Are there contradictions?" **AND** see new papers appear in the 3D graph automatically as research progresses.

## Architecture Decisions

### Why Overlay on Phase 3?
- **Reuse**: 3D graph foundation already proven (>30 FPS, <2s physics)
- **Context**: Papers + decisions together show complete reasoning landscape
- **Visual Hierarchy**: Can toggle decision view on/off without cluttering default view

### Why Not Separate App?
- **Overhead**: Obsidian plugin architecture is constraint; separate app = more work
- **Integration**: Decision-paper links are bi-directional in vault YAML
- **Efficiency**: Single MCP connection vs two

### Reasoning Chain Visualization (Flowchart vs Timeline)?
- **Flowchart** (chosen): Better for showing dependencies between steps
- Shows which steps blocked/enabled others
- More visual impact for complex chains
- Easier to annotate with confidence scores per step

### 2D vs 3D for Cascades?
- **2D Force Graph** (chosen): Cascades are already complex; 3D would add cognitive load
- Force-directed layout shows relationships clearly
- Easier to label edges (dependency_type, impact_level)
- Cascades may have >50 nodes; 3D might be overwhelming

## Risks & Mitigations

| Risk | Probability | Mitigation |
|------|-------------|-----------|
| SurrealDB offline | Medium | LRU cache (5min TTL) + fallback to vault notes only |
| Cascade queries slow (deep trees) | Medium | Limit depth to 5 levels, paginate results >50 nodes |
| 3D graph FPS drops with decision overlay | Low | Use LOD (level-of-detail) nodes, only render visible |
| Reasoning chains too verbose | Low | Truncate to 10 steps, show "More..." expandable |
| Decision-paper linking incomplete | Low | Already linked in vault YAML; validate during load |
| MCP tool API change | Low | Version pin; abstract in SurrealDBClient.ts for easy updates |
| **NEW: File watcher triggers too often** | Low | Debounce file changes (100ms), only re-index on .md files in /papers/ |
| **NEW: Paper ingestion stalls graph** | Low | Background worker for dimension calculation, don't block rendering |
| **NEW: Orphaned paper references** | Low | Validate all decision-paper links on startup + ingestion |

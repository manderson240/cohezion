# Plan: Auto-lint Hook for Python File Edits

## Context

After reviewing `~/.claude/settings.json` and `.claude/settings.json`, the setup is mature but missing automatic lint enforcement. Currently, `ruff` violations in edited Python files are only caught if explicitly run or tests are invoked. A `PostToolUse` hook on `Edit|Write|MultiEdit` that runs `ruff check --fix` on changed `.py` files will silently maintain code quality with zero friction.

Adding to **global settings** (`~/.claude/settings.json`) so it benefits all Python projects, not just cohezion. With `|| true` guard, it fails silently on non-Python projects.

## Target File

`~/.claude/settings.json` — merge into existing `hooks.PostToolUse` array (currently has one entry for `Bash` → `post-bash-cleanup.sh`).

## Hook to Add

```json
{
  "matcher": "Edit|Write|MultiEdit",
  "hooks": [
    {
      "type": "command",
      "command": "jq -r '.tool_input.file_path // empty' | { read -r f; [[ \"$f\" == *.py ]] || exit 0; root=$(git -C \"$(dirname \"$f\")\" rev-parse --show-toplevel 2>/dev/null) && cd \"$root\" && uv run ruff check --fix \"$f\"; } 2>/dev/null || true",
      "statusMessage": "Linting..."
    }
  ]
}
```

**Command breakdown:**
- `jq -r '.tool_input.file_path // empty'` — safely extracts file path from stdin JSON
- `{ read -r f; ... }` — reads into quoted variable (no word-splitting on spaces)
- `[[ "$f" == *.py ]] || exit 0` — skips non-Python files
- `git rev-parse --show-toplevel` — finds project root so ruff uses the correct `pyproject.toml` config
- `cd "$root" && uv run ruff check --fix "$f"` — runs ruff with project config
- `2>/dev/null || true` — suppresses errors and prevents hook from blocking Claude

The architecture, at a glance

Single JourneyNexus service owns lazy singletons for FLUME, Quadrature, and Omni. Thin FastAPI router exposes 5 endpoints. Next.js dashboard consumes them via SSE and fetch. Zero modifications to QuadratureNexus or JourneyTracker.

★ Design principle — non-destructive wiring

Every change is additive. The legacy /api/journeys/{id} route still works. The 4-voice deliberation is the real QuadratureNexus.deliberate() — no parallel reviewer. The TTS path is the real DirectLemonadeTTSTier. The plan explicitly rejected deletions in favor of integration.

★ How it works

QuadratureNexus.deliberate() returns a QuadratureResult. The JourneyNexus.quadrature() service maps that result into the dashboard-friendly voice_responses shape, and appends one EVOEvent per voice into the in-process EVOStream deque. The SSE endpoint /api/journey-nexus/stream/evo yields those events as they arrive. The dashboard's useEVOStream hook consumes them with exponential-backoff reconnect.

3 integration bugs caught at the live API (not by unit tests)

This is the core lesson the session enforced: tests passing is necessary but not sufficient. Three real defects slipped past the unit test layer and were caught only by hitting the live API.

Bug 1 — asyncio.to_thread over an async function

# Wrong (looked plausible, passed unit tests):
result = await asyncio.to_thread(nexus.deliberate, proposal)
# AttributeError: 'coroutine' object has no attribute 'responses'

# QuadratureNexus.deliberate is `async def` — to_thread wraps a coroutine in a Future,
# and the Future doesn't quack like QuadratureResult. The error message hides the real cause.

# Right:
result = await nexus.deliberate(proposal)

The unit-test mock was a sync def deliberate — so the test passed while the real path broke. Discriminating test added: inspect.iscoroutinefunction() on the fake's deliberate method, so a regression to the to_thread pattern can't pass the test suite silently.

Bug 2 — Seeder / reader schema drift

# Seeder wrote (canonical shape from existing corpus):
{ "journey_id": "...", "summary": "...", "trajectory": [...] }

# But summarize() reader expected:
{ "id": ..., "agent_name": ..., "intent": ..., "trajectory_length": ... }

# /api/journeys returned nulls for all 3 seeded journeys.

Fix: additive — added reader-contract aliases (id, agent_name, intent, trajectory_length) to the seeded dict, preserving the canonical journey_id/summary/trajectory keys. Non-destructive per the wiring policy.

Bug 3 — EVOStream had no producer

# Service had EVOStream (subscribe, add, snapshot) — but nothing called .add().
# /api/journey-nexus/evo/snapshot returned [] forever.

# Fix: in JourneyNexus.quadrature(), after the deliberation:
for vr in voice_responses:
    self._evo_stream.add(EVOEvent(
        id=str(uuid.uuid4()),
        timestamp=time.time(),
        journey_id=journey_id,
        voice=vr["voice"],
        kind="quadrature_deliberation",
        score=vr["approval_score"],
        z_256=[],                          # QuadratureNexus doesn't currently emit 256D
        state_12d=list(journey["initial_axiomatic"]),
    ))

The plan called for "live in-process stream backed by QuadratureNexus emissions" — the infrastructure was there, the wiring wasn't. Now 4 events per deliberation land in the EVOStream and the SSE endpoint yields them.

★ Reusable pattern — integration boundary check

For any service-layer work: the "did the wiring actually happen" question is best answered by hitting the live HTTP endpoint, not by reading the test results. The three bugs above all had green unit tests because unit tests mock the boundary. Live API calls reveal whether the production wiring is real.

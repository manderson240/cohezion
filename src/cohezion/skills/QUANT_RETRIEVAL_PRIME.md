# SKILL: QUANT_RETRIEVAL_PRIME

## DOMAIN EXPERTISE
Expert retrieval interface for Cohezion's SurrealDB v3.3.0 knowledge mesh. Instructs agents on searching like a 2010 Quant by combining exact metadata filters, dense vector similarity, lexical keyword matching, and graph relationship hops. Prevents context poisoning by requiring early retrieval quality gating before reasoning.

## KEY TEXTS & CONCEPTS
- **The Retrieval Problem (BrowseComp-Plus)**: Model intelligence collapses from 93% to 14% under poor retrieval.
- **Search Like a 2010 Quant (Bratseth Thesis)**: Agents must use multi-faceted structured queries instead of short human-style text prompts.
- **Schema-to-Skill**: Semantic understanding of field definitions, filter capabilities, and graph edges.
- **Early Quality Gate**: Halt execution if top retrieval score < 0.65 to avoid hallucinating over poisoned context.

## AGENT-READY SCHEMAS & SEMANTIC FIELD GUIDANCE

### Table: `goal`
**Purpose**: Long-horizon mission objectives, Kaggle track milestones, and high-level targets.

| Field | Type | Filterable | Semantic Meaning | Example |
|---|---|:---:|---|---|
| `id` | `record` | ✓ | Unique goal ID, e.g. goal:arc_agi_2_top10 | `goal:arc_2_ascension` |
| `title` | `string` | ✓ | Human-readable mission summary | `Ascend ARC-AGI-2 to Top 10` |
| `competition` | `string` | ✓ | Kaggle competition slug identifier | `arc-prize-2026` |
| `status` | `string` | ✓ | Lifecycle state: 'active', 'completed', 'blocked' | `active` |
| `target_score` | `float` | ✓ | Target leaderboard / validation evaluation score | `0.85` |
| `created_at` | `datetime` | ✓ | ISO timestamp when the goal was initialized | `2026-10-15T00:00:00Z` |

**Graph Traversals**: `->informs_goal->`, `<-informs_goal<-`

**Quant Query Templates**:
```sql
SELECT * FROM goal WHERE competition = 'arc-prize-2026' AND status = 'active';
SELECT * FROM goal:arc_2_ascension<-informs_goal<-loop_trace;
```

### Table: `loop_trace`
**Purpose**: Deterministic iteration logs recording hypothesis execution, code diffs, and scalar scores.

| Field | Type | Filterable | Semantic Meaning | Example |
|---|---|:---:|---|---|
| `id` | `record` | ✓ | Unique loop run record ID | `loop_trace:run_101` |
| `goal_id` | `record` | ✓ | Associated parent goal | `goal:arc_2_ascension` |
| `epoch` | `int` | ✓ | Current iteration counter within loop | `42` |
| `outcome` | `string` | ✓ | Result state: 'SUCCESS', 'FAILURE', 'INCONCLUSIVE' | `SUCCESS` |
| `scalar_score` | `float` | ✓ | Objective function outcome value | `0.9430` |
| `latency_ms` | `float` | ✓ | Inference wall-clock duration in milliseconds | `1840.5` |

**Graph Traversals**: `->informs_goal->goal`, `->verifies_segment->plan_segment`

**Quant Query Templates**:
```sql
SELECT * FROM loop_trace WHERE outcome = 'SUCCESS' ORDER BY scalar_score DESC LIMIT 5;
SELECT id, scalar_score, latency_ms FROM loop_trace WHERE goal_id = goal:rsna_knee;
```

### Table: `agentic_contract`
**Purpose**: Typed contracts generated by read-only IdeationAgent containing falsifiable rubrics (arXiv:2610.18933).

| Field | Type | Filterable | Semantic Meaning | Example |
|---|---|:---:|---|---|
| `id` | `record` | ✓ | Unique contract ID | `agentic_contract:c1` |
| `title` | `string` | ✓ | Concise title of proposed hypothesis | `Modulo Error Routing` |
| `falsifiable_hypothesis` | `string` | ✗ | Specific falsifiable scientific statement | `Modulo error routing prevents gradient attenuation in hidden layers.` |
| `worker_id` | `string` | ✓ | Originating worker beam identifier | `worker_0` |
| `target_rubrics` | `array` | ✗ | List of programmatic rubric checks that must be satisfied | `[{'id': 'R1_DALE'}]` |

**Graph Traversals**: `->contract_evaluated_by->attempt_outcome`

**Quant Query Templates**:
```sql
SELECT * FROM agentic_contract WHERE worker_id = 'worker_0' ORDER BY created_at DESC LIMIT 5;
```

## INSTRUCTION
1. Formulate a rich `QuantQuery` specifying `table`, `structured_filters`, `lexical_terms`, and optional `graph_relation`.
2. Invoke `QuantRetriever.retrieve(query)` to obtain ranked `RetrievalItem` objects.
3. Execute `QuantRetriever.evaluate_retrieval_quality(items)`. If `is_sufficient` is False, DO NOT GUESS OR HALLUCINATE.
4. Reformulate search terms or alert the orchestrator when `confidence_level == 'CRITICAL_DEFICIT'`.

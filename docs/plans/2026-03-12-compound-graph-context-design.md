# Compound Graph Context — Design Document

**Date**: 2026-03-12
**Status**: Approved
**Author**: Claude Code + Mike Anderson

## Problem

The vault's SurrealDB graph (1,601 neurons, 10,581 synapses) is powerful but passive.
Agents must explicitly know to query it and choose to do so. This creates three
compounding friction points:

1. **Cold start** — New sessions have zero graph awareness (~5-10K tokens burned orienting)
2. **Wrong-file reads** — Agents guess which files to read instead of letting the graph tell them
3. **Missed connections** — Bridge neurons exist but nobody asks for them at the right moment

These costs multiply: cold start x wrong reads x missed connections = exponential token
waste across sessions.

## Solution: Two-Layer Compound Context

### Layer 1: Graph Briefing (Pre-computed, Zero Runtime Cost)

A new `briefing` command in `graph_context.py` generates `metabolism/graph-briefing.md`
on the dreaming cron schedule. Agents read this ONE file at session start (~1000 tokens)
for ambient vault awareness.

**Content sections:**
- Vitals: neuron/synapse counts, stage distribution
- Hot Neurons: top 15 by activation with cluster/stage
- Cross-Domain Bridges: top 10 neurons bridging different clusters
- Attention Needed: embryos, low-coherence clusters, disconnected neurons
- Recent Activity: neurons modified in last 24h with neighborhoods

**Integration:**
- Generated by: `python3 scripts/graph_context.py briefing`
- Output to: `metabolism/graph-briefing.md`
- Triggered by: dreaming cron (`scripts/dreaming-cron.sh`)
- CLAUDE.md directive: "Read `metabolism/graph-briefing.md` at session start"

### Layer 2: Context Hook (Reactive, Task-Aware)

A `UserPromptSubmit` hook that extracts keywords from the user's prompt, queries the
graph, and injects compact context before the agent responds.

**Flow:**
1. Receive prompt text via `$CLAUDE_USER_PROMPT`
2. Extract 1-3 candidate keywords (sliding windows, skip stopwords/commands)
3. Query `graph_context.py resolve` for neuron matches
4. If match found, query `graph_context.py search` for context
5. Print compact output to stdout (injected as hook output)
6. If no match, print nothing (zero token cost)

**Keyword extraction** — deliberately simple, stdlib only:
- Split on whitespace, remove stopwords
- Try 2-3 word sliding windows first (better for multi-word titles)
- Fall back to single significant words
- Skip pure-command prompts ("commit", "yes", "continue")
- Max 3 keywords tried, first match wins

**Output format** (~300-500 tokens when fired):
```
--- Graph Context: "exotic vacuum" ---
[#####] 1.00 Exotic Vacuum Objects (mature, cortex, out:8 in:5)
  Path: cortex/exotic-vacuum-objects.md
  Tags: physics, vacuum-engineering, metamaterials
  -> [####.] 0.85 Metamaterial Waveguides (cortex)
  -> [####.] 0.80 Negative Energy Density (cortex)
  <- [#####] 1.00 Sarfatti Post-Quantum (cortex)
  Cluster siblings: 5 in cortex (avg act: 0.64)
--------------------------------------
```

**Performance budget:**
- Keyword extraction: <10ms (pure string ops)
- Graph query: ~200ms (one HTTP call to SurrealDB)
- Total hook latency: <300ms
- Silent on non-matching prompts (zero cost)

**Graceful degradation:**
- SurrealDB down -> prints nothing, agent proceeds normally
- No keyword matches -> prints nothing, zero token cost
- Timeout (5s) -> hook killed, agent proceeds

## Compound Effect

Layer 1 (briefing) fixes cold start. Layer 2 (hook) fixes wrong reads.
Together they fix missed connections. Each session's improved output feeds back
into the graph (via vault_sync.py), which improves the next session's briefing
and hook results.

**Token economics:**
- Current: ~18.5K tokens per task (orient + guess reads + miss connections)
- Proposed: ~9.4K tokens per task (briefing + hook-guided reads)
- Savings: ~50% per task, with quality improvement

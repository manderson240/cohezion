## 3. Hypotheses (all falsifiable)

- **H1 — Specialization:** The best model differs across ≥2 task categories (no single model Pareto-dominates). *Falsified if one model wins every category.*
- **H2 — Config sensitivity:** For ≥1 (model, category), a promoted non-default config (temperature / prompt style) improves accuracy by ≥10 points over default. *Falsified if config search never beats defaults.*
- **H3 — Sustained stability:** Per-model canary TPS median drifts ≤10% from its first-6h baseline over ≥72 h, and TPS↔SoC-temp correlation stays |r| < 0.3. *Falsified by sustained drift or thermal coupling.*
- **H4 — Determinism:** temp=0 canary outputs are hash-stable per (model, prompt) across the whole run. *Falsified by any hash flip.*
- **H5 — Compute-normalized ranking differs:** The quality-per-second leaderboard ranks differently from the raw-accuracy leaderboard (small models win when normalized). *Falsified if rankings coincide.*

## 4. Design

### 4.1 Roster
- **Default:** the 4 installed generative FLM models (≤5 GB weights each).
- **Extensible:** `roster` list in `manifest.json`; adding an uninstalled catalog model is an explicit operator action (`--pull <id>`), never automatic (multi-GB downloads).
- **Excluded by default:** `gpt-oss-20b-FLM`, `qwen3.6-moe-35b-a3b-FLM` (heavy — OOM gate §4.6 must clear them explicitly), `whisper*`, `embed-*`, vision/translate specialists (no matching task battery yet).

### 4.2 Task battery — procedurally generated, exactly verifiable
All tasks come from seeded generators (contamination-free, infinite supply, gold answer computed by construction). Categories map onto `task_classifier` output types — that is the routing hook:

| Category | Generator | Verification | Sampling |
|---|---|---|---|
| `arithmetic` | 3–5-step word problems from templates | gold int equality | k=3, temp per config (self-consistency majority) |
| `extraction` | fact-grid paragraph → "what is field X?" | exact match | k=1, temp=0 |
| `json_format` | data → JSON matching mini-schema | parse + deep equality | k=1, temp=0 |
| `instruction` | constraints ("exactly N words", "ends with X") | programmatic check | k=1, temp=0 |
| `classification` | templated unambiguous sentiment/category | label match | k=1, temp=0 |

Answer extraction: strip `<think>…</think>` blocks first (deepseek), then parse the final `#### <answer>` marker, falling back to last-number / fenced-JSON heuristics. Normalize whitespace before hashing canary outputs.

### 4.3 Round protocol (the gauntlet lap)
A **round** = one model's turn on the NPU:
1. **OOM gate** (§4.6). Skip turn if it fails.
2. **Load** model via `POST /api/v1/load`; record swap time; verify via `/api/v1/health` that the model is `ready` on `device: npu` (FLM-only guard: id must end `-FLM` *and* device must be `npu`).
3. **Canary battery:** 3 fixed prompts, temp=0, max_tokens=256 → TTFT-proxy latency, TPS, normalized-output sha256.
4. **Telemetry sample:** k10temp, MemAvailable, loadavg, time-of-day.
5. **Trial slice:** run task trials for a fixed **wall-clock slice** (default 15 min) — not a fixed count. Fast models bank more trials (feeds H5). Category selection per trial ∝ Wilson-CI width for that (model, category) — uncertainty-directed sampling.
6. Append every trial + the round summary to `results.jsonl`. Accepted self-consistent, correct reasoning traces additionally go to `traces.jsonl` (SFT corpus by-product, Autodata-style).

Round-robin over the roster; one lap ≈ 4 × (15 min + overhead) ≈ 65–70 min → ~21 laps/day, ~5 h of NPU time per model per day.

### 4.4 Recursive learning (the "learn from the gauntlet" loop)
1. **Config search:** per (model, category), a small config space — temperature {0.3, 0.7, 1.0} for `arithmetic`; prompt style {direct, step_by_step, strict_format} for all. ε-greedy: after ≥20 baseline trials, promote the best-accuracy config into `manifest.json`; keep exploring at ε=0.15. Promoted configs are used by subsequent rounds → **the gauntlet's own results change how it runs**.
2. **Leaderboard regeneration** every 6 laps: `leaderboard.json` — per (model, category): accuracy + Wilson CI, mean TPS, quality-per-second (accuracy × trials/hour), determinism verdict, drift check vs first-6h baseline.
3. **Vault write-back (Wire-at-Creation target):** on each regeneration, write
   - `~/vaults/cohezion-vault/model_performance/npu_gauntlet_leaderboard.json` (machine-readable, supersedes the stale 2026-04 entry),
   - `~/vaults/cohezion-vault/reports/npu-gauntlet-latest.md` (human summary + hypothesis verdicts),
   - append-merge measured FLM entries into `model_recommendations.json` (non-destructive: never remove existing entries).
4. **Downstream consumer (declared follow-up, not built now):** `task_classifier` / CostAwareRouter reads the leaderboard to pick the NPU model per output_type. The gauntlet produces the data; the wiring PR is a separate, permission-gated change.

### 4.5 Stability axis
The per-round canary + telemetry stream is the 24/7 sustained-load experiment (H3/H4): drift of TPS medians, hash flips, thermal correlation — per model, since each model revisits the NPU ~21×/day, interleaved across day/night ambient cycles.

### 4.6 OOM & safety gates (hard rules, from harness N3/K1)
- **RAM floor:** before every load, `MemAvailable − est_weights ≥ 16 GB` (weights estimate: catalog size if known, else `0.7 GB × B-params` for Q4). Fail → skip turn, log `oom_gate_skip`.
- **FLM-only:** refuse any model id not ending `-FLM`; verify post-load `device == npu`. The daemon can never touch GPU/CPU models.
- **Bounded generation:** max_tokens ≤ 2048 (thinking models) / 1024 (others); never send `ctx_size` overrides; FLM recipes self-bound ctx (harness: ctx N/A = safe).
- **One heavy thing:** only one FLM model loaded at a time (NPU slot enforces this); loads serialized; no concurrent GPU work initiated by the daemon.
- **Crash isolation:** every trial and every round wrapped in try/except (Kaggle v25 lesson: one NameError must not kill the loop); per-call timeout 300 s; 3 consecutive round failures → back off 15 min and continue.
- **Thrash detection:** if post-load health shows the NPU occupant changed between our rounds (another consumer reloaded llama3.2-1b), count a `swap_conflict` and continue — the metric surfaces contention rather than fighting it.
- **Clean shutdown:** SIGTERM/SIGINT flush + heartbeat file (`heartbeat` mtime = liveness).

## 7. Risks

| Risk | Mitigation |
|---|---|
| OOM from heavy roster additions | §4.6 gate + heavy models excluded by default |
| NPU slot contention with fleet (llama3.2-1b consumers) | swap_conflict metric; fleet currently idle 3+ days; operator can `--pause` via manifest flag |
| lemond degraded state (httpx timeouts while curl works) | known failure mode → round failure backoff; report surfaces consecutive-failure streaks |
| Daemon dies with agent session | launch doc: persistent run requires user-terminal start (`!` prefix); heartbeat makes death visible |
| Answer-extraction brittleness inflates "wrong" | extraction unit-tested per model output style; abstentions tracked separately from errors |

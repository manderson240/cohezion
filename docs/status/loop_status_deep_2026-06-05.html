Deep-dive 1 · Event-driven OOM (3 layers)

OOM avoidance moved from a single reactive check at load-time to a three-layer sense → gate → act system. The Strix Halo box is memory-tight (128 GiB, ~93 used) and the old budget model was swap-blind — it could approve a load while swap was already thrashing.

┌─────────────── SENSE ───────────────┐ ┌──── GATE ────┐ ┌──── ACT ────┐ MemoryPressureMonitor (143 LOC) can_load_model OOMEvictor (209) classify(avail, swap) → OK/WARN/CRIT (3 stacked checks) on rising CRIT → emits event ONLY on level TRANSITION ───────────┬──────────► evict least-pref ▲ │ model, fail-soft PressureDriver.tick() samples on cadence loads_blocked() PressureDriver.run()

Layer 1 — the gate (d7e6acd1d, resource_manager.py)

A hard gate added on top of the budget model. oom_safe_to_load(size_gb) blocks when avail ≤ size×1.2 or when size ≥ 20 GB and swap ≥ 50% — the literal encoding of harness K1 / strix-halo rule-5 ("never pin >20 GB while swap >50%").

Layer 2 — the monitor / sense (ec991a291, memory_pressure.py)

The key design choice is emit-on-transition, not emit-on-poll. Repeated evaluations at the same level emit nothing; only a level change fires an event. That's what makes the rest of the system event-driven rather than poll-coupled.

def evaluate(self, *, snapshot=None):
    snap = snapshot or _read_system_memory()   # (avail_gb, swap_pct), fail-soft None
    level = classify_pressure(*snap)             # CRIT if avail<8 or swap≥50; WARN if <16 or ≥30
    if level != self._level:                     # ← emit ONLY on transition
        event = MemoryPressureEvent(level, self._level, ...)
        self._level = level; self._notify(event)
    return level

Layer 3 — the evictor / act (85fa0683b, oom_evictor.py, item 1)

Subscribes to the event stream and reacts to exactly one condition: level==CRITICAL and event.rising. It unloads the least-preferred loaded model — the highest priority-number in the registry convention (lower = preferred). Non-destructive: the default lister returns only models it can map to the fleet registry, so unknown/system processes are never touched.

def on_event(self, event):
    if event.level == PressureLevel.CRITICAL and event.rising:
        return self.evict_one()   # one eviction per rising edge — not WARN, not sustained

Deep-dive 2 · Routing intelligence

Electricity + quality (e046d4b0a)

On a $0 local fleet, every lane's cost_usd is zero — so the dollar-based Feynman path weight (CC2: quality × exp(−100·cost)) can't differentiate them. Electricity is the missing axis. The weight was extended to quality × exp(−100·cost) × exp(−λ_E·joules) with λ_E=0.01. Crucially the energy term defaults to 0, so feynman_path_weight(0.5, 0.0) stays byte-identical and the CC2 harness check (local(0.5,0) > cloud(1.0,0.01)) still passes.

Task-aware selection (model_registry.get_best_for_task)

Routing now classifies the task string to a Task type and asks FleetRegistry.for_task() for the registered specialist — "the right model for the right task" — before falling back to the complexity router. Ranking is quality-first, watts-as-tiebreak:

def _rank(c):
    return (c.priority, _LANE_WATTS.get(c.lane, _DEFAULT_WATTS))
    # priority FIRST (encodes task-affinity) → watts NEVER override a better-fit model.
    # _LANE_WATTS = {npu:2, igpu:35, cpu:55}; NPU wins only on a priority TIE.

Routing-decision corpus (22ac729d3, item 2)

Every decision now appends one JSON line — (task_class, chosen_model, lane, fell_back, outcome?) — to ~/.cohezion-research/logs/routing_log.jsonl, wired at all three return points (specialist hit → fell_back=False; router fallback / no-route → fell_back=True). Logging at all three, not just the happy path, is what keeps the corpus unbiased: the fell_back=True records are exactly the signal that reveals where task→specialist coverage is missing. Item 9 (now unblocked) will feed this into autoresearch to tune LANE_WATTS from real outcomes.

The non-obvious load-bearing detail: a pytest-skip guard (path is None and "pytest" in sys.modules → return None) so the suite never pollutes the training corpus, while tests inject an explicit path to verify writes.

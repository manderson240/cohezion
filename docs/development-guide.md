# Development Guide

_Generated by BMAD `/bmad-document-project` on 2026-04-22._

## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Python | **3.11.\*** | Locked in `pyproject.toml`; incompatible with 3.12+ due to `torch==2.5.1+rocm6.2` ABI |
| uv | latest | **Mandatory**. Never use bare `pip`. |
| git + git-lfs | recent | `.gitattributes` tracks `*.so`, `*.whl`, `*.pt`, `*.pkl`, `*.jsonl`, etc. Run `git lfs install` once. |
| Bun | latest | For the web dashboard (`src/web/anima_dashboard/`) |
| Node.js | (optional) | Next.js tooling can fall back; Bun is preferred |
| Docker | optional | For SurrealDB + GoogleSQL sidecar |
| SurrealDB | `>=0.3.0` | `ws://localhost:8001?versioned=true`; SurrealKV backend |

**Hardware**: AMD Ryzen AI MAX+ 395 (16C/32T) + Radeon 8060S iGPU (unified LPDDR5X memory, 128 GiB). No CUDA. Torch must be the ROCm build. See [`HARDWARE_PROFILE_PRIME.md`](../HARDWARE_PROFILE_PRIME.md).

## First-time setup

```bash
git clone https://github.com/manderson240/cohezion.git
cd cohezion

# Backend
uv sync                                       # installs Python 3.11 + all deps
git lfs install && git lfs pull               # pull LFS objects

# Web dashboard
cd src/web/anima_dashboard
bun install
cd ../../..
```

## Environment

Environment variables are loaded from `.env` / `.env.development` / `.env.local` (all present at the repo root, typically empty by default). Sensitive secrets should never be committed — use `~/vaults/cohezion-vault/` via `cloud-vault-mcp`.

**Never** store `SUDO_PASSWORD` in `.env` for automation — use passwordless sudo or run interactively.

## Core commands

### Backend (via `make` — see `Makefile`)

```bash
make help                     # list all targets
make format                   # ruff format
make lint                     # ruff check --fix
make lint-check               # ruff check (no fix) + ruff format --check
make type-check               # mypy (permissive)
make test                     # uv run pytest tests/     (6,369 tests)
make test-fast                # -m fast    (<1s each, no live services)
make test-integration         # -m integration  (Ollama + SurrealDB required)
make test-smoke               # quick minimal subset
make validate                 # compound-loop validation (23 checks, ~18s)
make all                      # format + lint + type-check + test + all guards
```

Guard targets (run by `make all`):

| Target | Purpose |
|---|---|
| `agent-guard` | Sync specialist agent definitions across platforms |
| `a2a-guard` | Sync A2A protocol agent cards (`.well-known/agent.json`) |
| `mcp-guard` | Sync MCP configs + latency anti-pattern checks |
| `kg-guard` | Precipitate knowledge from high-coherence journeys |
| `data-mesh-guard` | Monitor Data Mesh registry SLA + quality |
| `health-guard` | Autonomic health + trajectory drift (background) |
| `async-guard` | Scan for sync I/O in async code |
| `routing-guard` | Sync model routing + provider configs |
| `skill-guard` | Validate skill metadata + FLUME compatibility |
| `root-guard` | Repo root health (items < 50) |

## Test strategy

- **Framework**: pytest 9 + pytest-asyncio + pytest-cov
- **Markers** (in `pyproject.toml`):
  - `fast` — unit tests, <1s each, no live services
  - `integration` — requires live Ollama / SurrealDB
  - `mcp` — requires vault access
- **Coverage**: HTML in `htmlcov/` after runs with `--cov`
- **Test isolation**: `tests/conftest.py` resets FLUME VAE + RL policy + logger singletons — **read this first**

Run single test:
```bash
uv run pytest tests/test_foo.py::TestBar::test_baz
```

Mock at source (not deep implementation):
```python
@patch("cohezion.swarm.compound_client.get_compound_client")
def test_something(mock_client): ...
```

## Coding standards (`CLAUDE.md` + `.claude/rules/`)

1. **`uv` only**, never bare `pip`
2. **Pydantic v2 at boundaries** (input/output); assertions for internal invariants
3. **Async + timeouts** for all I/O; no blocking calls in executors
4. **Specific exceptions + circuit breakers** via `cohezion.reliability.get_circuit()`
5. **No `except (SubclassError, Exception)`** stealth bare-except (L359)
6. **`inspect.signature` structural checks** before behavioral invariants (L366)
7. **`.venv/bin/python3` in subprocess calls**, not `sys.executable` (L367)
8. **Surgical commits**: `git diff --cached --name-only` before committing against a dirty tree (L363 + L368)
9. **Production files < 300 lines**; hard limit 500 → refactor immediately
10. **Correctness gate before performance**: assert shapes, known-input tests, reference-comparison, edge cases, THEN perf
11. **YAML frontmatter `.md`** (not JSON) for config/state humans may read
12. **FLUME-First**: new modules encode/decode through FLUME VAE (L215)
13. **Wire-at-Creation**: new modules declare a wiring target (L227)

## Worktree workflow

Multi-session worktree pattern is mandatory for concurrent work. See the `cohezion-worktree-workflow` skill and the global rule `cz-cli.md`:

```bash
cz worktree detect --json <slug>
cz worktree create --json <slug>                  # creates .worktrees/spec-<slug>/
# … do work in the worktree …
cz worktree diff --json <slug>
cz worktree sync --json <slug>                    # squash merge to base
cz worktree cleanup --json <slug>
```

## Context management

| Level | Action |
|---|---|
| < 80% | Normal |
| 80–89% | Wrap current task, avoid new complex work |
| ≥ 90% | **MANDATORY** handoff via `cz session send-clear <plan.md>` |

See `~/.claude/rules/context-continuation.md`.

## Vault-first knowledge

All session learnings go to `~/vaults/cohezion-vault/`, NOT directly to `MEMORY.md`. `MEMORY.md` is an auto-generated weekly cache of the vault. See the `cohezion-vault-workflow` skill.

## Pre-commit hooks

Enforce:
- `lfs-pointer-check` — large binaries must be LFS-tracked
- Schema validation on `settings.json`
- Repo-health: `.git/` size, `entire/` branch count, remote configured, LFS active, `git fsck` clean

If LFS breaks: `git lfs install && git add --renormalize .`

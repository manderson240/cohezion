# Deployment Guide

_Generated by BMAD `/bmad-document-project` on 2026-04-22._

## Infrastructure overview

- **Deploy target**: Google Cloud Run (Free Tier only — no instances when idle)
- **Local dev**: Bare-metal on AMD Ryzen AI MAX+ 395 (Strix Halo) — 128 GiB RAM, Radeon 8060S iGPU, ROCm
- **Local inference**: Ollama (4-concurrent model limit) preferred over cloud API
- **Database**: SurrealDB (`ws://localhost:8001?versioned=true`, SurrealKV backend)
- **IaC**: Minimal — `infrastructure/` directory and deployment-focused subpackage `src/cohezion/deployment/`

**Cost principle** (from `CLAUDE.md`): never incur cloud costs for workloads that can run locally.

## Deployment process

### Backend (FastAPI)

```bash
# 1. Verify gates
make lint-check && uv run pytest tests/ -q        # must pass

# 2. Build (no Dockerfile at repo root; containerize per target)
#    If cloud target requires a container, create a minimal image based on
#    python:3.11-slim and `uv sync --frozen`. The repo does not ship one.

# 3. Run locally to verify
uv run uvicorn cohezion.api:app --host 0.0.0.0 --port 8080

# 4. Deploy (Cloud Run example)
#    gcloud run deploy cohezion-api --source . --region us-central1 ...
```

### Web dashboard

```bash
cd src/web/anima_dashboard
bun install --frozen-lockfile
bun run build                                       # Next.js production build
bun run start                                       # or copy built output to a CDN
```

The web build can also be served as static assets under `src/cohezion/api/static/` by the FastAPI app for single-origin deployment.

## Environment configuration

- `.env` / `.env.development` / `.env.local` / `.env.production` — all present, typically empty in the checked-in version
- Secrets live in `~/vaults/cohezion-vault/` and are accessed via `cloud-vault-mcp`
- **Never** commit `SUDO_PASSWORD` to `.env`
- **Never** write secrets to temp files that persist

## Pre-deploy checks

```bash
make lint-check                               # ruff check + format check
make type-check                               # mypy
uv run pytest tests/ -q                       # full test suite
make validate                                 # compound-loop gate (23 checks)
make all                                      # all guards
```

**CI must pass** before any merge to `main`. Branch strategy:
- `main` — stable releases only
- `develop` — active development
- `feature/*` — new features
- `fix/*` — bug fixes

PRs target `develop`; periodic releases merge `develop` → `main`.

## Release process

1. Bump version in `pyproject.toml` following semver:
   - Breaking → major
   - Feature → minor
   - Fix → patch
2. Update `CHANGELOG.md`
3. PR to `develop`, then merge `develop` → `main`
4. `.github/workflows/release.yml` + `semver-check.yml` enforce the workflow

## Kaggle deployment (notebooks)

Per `CLAUDE.md` "Kaggle Blackwell Handshake": for Kaggle G4 (Blackwell) infrastructure, you must:

1. Set `"machine_shape": "NvidiaRtxPro6000"` and `"dockerImageVersionId": 31287` in notebook metadata
2. Copy `nvidia_utility_script` to `/tmp` and `chmod +x` the `ptxas-blackwell` binary
3. Set `os.environ["TRITON_PTXAS_PATH"]` to the `/tmp` binary path
4. Pre-authorize models in `"model_sources"` metadata

Driver: `.worktrees/nemotron-june/scripts/drive_nemotron.py` (quota: 5 submissions/day for Nemotron/AGI-Golf/ARC-Paper; 1/day for ARC-Code).

## Monitoring / observability

- `/observability/metrics` — Prometheus-style metrics (via `observability_endpoints.py`)
- `/observability/traces` — Execution traces
- `/health` — System vitals
- Cloud Run Free Tier means zero idle cost, so monitoring hits wake instances — batch health checks.

## Rollback

- `JourneyTracker.rollback()` for agent-level rollback
- `git revert` or `entire rewind` for code rollback (Entire.io installed via `entire enable`)

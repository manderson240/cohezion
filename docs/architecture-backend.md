# Architecture – Backend (`src/cohezion/`)

_Generated by BMAD `/bmad-document-project` on 2026-04-22._

## Executive summary

The Python backend is a service-oriented monolith implementing a **compound engineering loop**: human- or machine-authored PRIME skills flow through an 11-step `CompoundExecutor` pipeline, whose outputs feed a `RetrospectionEngine` that refines the skills themselves. The system is grounded in an explicit **physics model** — a 12-dimensional Riemannian manifold with SU(2) gauge structure — so agent behavior is constrained by manifold geometry rather than reward-penalty shaping.

Canonical context: [`CLAUDE.md`](../CLAUDE.md) · theory: [`.agent/COHEZION_CHARTER.md`](../.agent/COHEZION_CHARTER.md) · constraints: [`.agent/CONSTITUTION.md`](../.agent/CONSTITUTION.md)

## Architecture pattern: Compound Engineering Loop

The system's defining pattern. Flow:

```
┌──────────────────────────────────────────────────────────────┐
│ PRIME skill (markdown) ──► InstructionExpander               │
│                                   │                          │
│                                   ▼                          │
│                            PlanExecutor                      │
│                                   │                          │
│                                   ▼                          │
│  ┌──────────────  ExecutionOrchestrator (11 steps)  ──────┐  │
│  │ 1. RequestAlignmentAnalyzer (coherence/completeness)   │  │
│  │ 2. GlobalMetricsAggregator (instance metrics)          │  │
│  │ 3. DegradationDetector (thermal + quality)             │  │
│  │    → feedback to CostAwareRouter + healing/resilience/ │  │
│  │ 4. JourneyTracker (12D universe position)              │  │
│  │    + JEPA surprise                                     │  │
│  │    + bioelectric percolation → SurrealDB               │  │
│  │ 5. OuroborosBridge (physics coherence check)           │  │
│  │ 6. Mycelium (change correlation)                       │  │
│  │ 7. MyceliumRegistry (auto-capture exec patterns)       │  │
│  │ 8-11. Executor-specific steps                          │  │
│  └────────────────────────────────────────────────────────┘  │
│                                   │                          │
│                                   ▼                          │
│                         RetrospectionEngine                  │
│                       (learnings + anomalies + pivots)       │
│                                   │                          │
│                                   ▼                          │
│                          SkillRefiner                        │
│                                   │                          │
│                                   ▼                          │
│                      SkillConsensusVoter                     │
│                      (multi-agent validation)                │
│                                   │                          │
│                                   ▼                          │
│              Updated Skill ──► (loop continues)              │
└──────────────────────────────────────────────────────────────┘
```

CLI entry: `uv run python scripts/drivers/compound_cycle.py` · Or `/compound` API endpoint.

## Data architecture

- **Primary store**: SurrealDB with SurrealKV backend, `?versioned=true` for temporal queries.
- **Connection**: `ws://localhost:8001` · `127.0.0.1` only (never exposed).
- **Schema style**: bi-temporal (`valid_from` / `valid_to`) on neurons, `agent_journey`, `universe_node`.
- **V-Model tables**: `vmodel_gate`, `traces`, `hash_chain`, `proof_obligation` (Session 96b).
- **Integrity**: hash-chain audit trail in `JourneyTracker` (OLIF mitigation).
- **Backup**: SurrealKV migration from RocksDB (Session 96b).

See [`data-models-backend.md`](./data-models-backend.md) for entities + schemas.

## Testing strategy

- **Fast tests** (`-m fast`): <1s each, no live services
- **Integration tests** (`-m integration`): require Ollama/SurrealDB
- **MCP tests** (`-m mcp`): require vault access
- **Smoke tests**: `make test-smoke`
- **Test isolation**: `tests/conftest.py` resets FLUME VAE + RL policy + logger singletons — **read this first** before writing tests
- **Mock at source**: e.g. `@patch("cohezion.swarm.compound_client.get_compound_client")` — never mock deep implementation

## Known constraints & design mandates

1. **FLUME-First**: new modules MUST encode/decode through FLUME VAE (Learning 215).
2. **Wire-at-Creation**: new modules declare a wiring target (DegradationDetector, CapabilityMatrix, CompoundExecutor step, or Hookify rule) at creation (Learning 227).
3. **Async only**: all I/O is `async/await` with timeouts. No blocking calls in executors.
4. **No `except Exception` wide tuples** (Learning 359): supertype + subtype in one tuple = stealth bare-except. Use only sibling/unrelated types.
5. **Subprocess into Cohezion via `.venv/bin/python3`** (Learning 367), not `sys.executable` — system-shell contexts lose the venv.
6. **Surgical commits** (Learning 363 + 368): verify `git diff --cached --name-only` before committing against high-churn trees.
7. **V-Model structural-before-behavioral** (Learning 366): pair every keyword/signature invariant with a ~1ms structural check at harness start.
8. **Diagnostic sidecars** (Learning 362): write full stdout+stderr next to summary reports when subprocesses can fail silently.
9. **Calibration as signal** (Learning 369): empty model output on structured prompts is honest abstention — treat as no-op, don't retry.

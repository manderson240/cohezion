## Notes
- **Elegant simplicity (audit dimension, 2026-06-06, user request):** the audit loop measures the structural COST of code — control-flow complexity (item 43), needless indirection (item 44), cohesion/LCOM4 (item 10), reachability (the wiring sweep) — and flags OUTLIERS for human/build-loop judgment. Guardrails: (a) OBJECTIVE metrics only, no subjective "elegance score" (false precision on a subjective thing — a number is a smell, not a verdict); (b) REPORT-ONLY, never auto-refactor (behavior-changing/destructive, against the non-destructive policy); (c) it is the DUAL of the wiring loop's "no fake edge" rule — complexity, like an import edge, must EARN ITS KEEP; ceremony without function is the opposite of simplicity.
- Items 1–5 are additive/safe; 6–8 are behavior-changing (land behind the falsifiable check, else report-only).
- **Scope-expansion directive (2026-06-06):** the loop no longer terminates at a fixed list. Each tick, after completing one item, it APPENDS ≥1 new falsifiable item that extends a thread into adjacent territory (a new `Task` slot, an unused neuron `country`, a new measurement, a new resilience/telemetry check, or the next wiring package). New items MUST be additive + falsifiable + invariant-respecting + non-fabricated (research-gated ids stay TODO until the research loop verifies them). The loop only STOPS/notifies when scope cannot be expanded without a human decision (every frontier item is BLOCKED on human input).
- **Loop-doctrine directives (2026-06-07, user):** four standing changes to how the loops run.
  (1) **Every interaction feeds a loop** — each user interaction (a question, a "consider <link>", a bug report, a directive) must be routed INTO an existing loop (build/wiring/research/remediation) or SEED a NEW loop, never handled one-off-and-forgotten. The artifact: a backlog item, a feed round, a ledger entry, a remediation finding, or a new loop arm. (2) **"Just about infinite loops"** — the loops are standing/recurring and self-expanding (scope-expansion + remediation arms); they only halt for a human-gated decision, then resume. (3) **Polyglot refactor as a loop arm** — item 124 (report-only, per-language native tools, non-destructive). (4) **Safeguards: adhere AND improve** — every tick respects the calibrated invariants (A3/A4/A5/CA1/CC2/LM6 + K1/rule-5 OOM + non-destructive wiring + surgical commits) AND may PROPOSE a better safeguard (a new harness invariant, a tighter resource gate, a new structural-before-behavioral check) as an additive, falsifiable item — the resource-aware router (item 122) is the first such self-authored safeguard (it would have prevented the fleet-saturation that broke the bot). Safeguard improvements are themselves additive + report-only-until-proven; never weaken an existing invariant without a human decision. (5) **Usage throttle — never run out of Claude (item 134, 2026-06-07)** — at the START of every self-paced loop tick, run `python scripts/loop_usage_guard.py` and OBEY the action: `proceed` → normal; `throttle` → widen the ScheduleWakeup delay (≥3600s) and shift inference to the local fleet (`extend_claude`) instead of spending agent turns; `halt` → do NOT re-arm ScheduleWakeup (stop autonomous wakeups; only user-driven turns + local-fleet work continue), and PushNotification the user. This gates the Claude-Code plan quota (the session/weekly limits), NOT the API \$ budget. The whole point of the great local inference we keep improving is that it's the escape valve — throttling means MORE local, never a hard stop on capability. (6) **RSI safeguard grounding (Anthropic Institute "When AI Builds Itself", 2026-06-07, FEED Round 32)** — these loops sit at the piece's *present* stage (agents write/edit/run code + delegate), NOT autonomous successor-design; calibrate claims accordingly.

The Orchestration Model — Why This Matters

Tiered orchestration generalizes the Claude Code /advisor pattern: a cheap primary model produces a response, a smarter secondary model audits it, and the system escalates only when quality gates fail. Applied recursively, this yields agents → sub-agents → sub-sub-agents, each tier adding judgment without paying its cost unless needed.

Tier 0 — NPU (Gemma-4-E2B)
~80 ms TTFT, $0 cost, first attempt on every request
Tier 1 — iGPU ROCWMMA (Gemma-4-26B MoE)
Escalated when tier-0 trust gate fails; still $0 cost
Tier 2 — CPU (deep reasoning)
For long-context or tool-use prompts; still local, still $0
Tier 3 — Claude API (Haiku → Sonnet → Opus)
Final fallback when local confidence < threshold

Measured on live demo: 5/5 prompts succeeded at Tier 0 — zero escalations, zero cost, 2.7 s wall-clock. The same pipeline routes to Claude when local quality gates fail, preserving answer quality under a strict $ budget.

Honest Retrospective — What Hurt

  • n=5 warm-loop observations got promoted to typed p50/p95 registry fields. Caught by scientific-rigor review. A p95 needs ≥20 observations to be statistically meaningful. Fixed: typed fields nulled until full benchmark populates them.
  • --yolo flags slipped into production dispatch paths. Any prompt reaching Hermes or Gemini could have executed shell commands without confirmation. Fixed: flags removed / downgraded to plan.
  • Config A (Claude-only) silent failure in pilot benchmark. claude -p returned empty stderr — no diagnostic trail. Partial fix (PILOT flag). Full fix (stderr sidecar + I2b invariant) deferred as ROADMAP P1.
  • Benchmark header disclosed corpus of 20 but actually ran 3. Caught by scientific reviewer. Fixed: header now shows executed N of 20 available; Status: PILOT.
  • Reasoning-mode demo stochasticity. Gemma-4 FLM used all 256 max_tokens on <thinking>, leaving empty visible output in some runs. Fixed: demo uses max_tokens=1024 non-streaming; quirk documented in local_environment_quirks.md.
